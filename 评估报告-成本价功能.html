核心结论

在自选股上记录成本价（+可选持仓数量），在自选面板与悬浮提示中展示持仓盈亏（金额 + 百分比）。数据存储复用「备注」的成熟模式：localStorage + 服务端 costs.json 双写，清浏览器数据不丢（吸取 v57 教训）。现有代码无冲突：自选行渲染（wlRowHtml）、悬浮提示（showWlTip）、服务端 notes/watchlist 存储均为现成模板，改造点清晰。

一、需求定义

项说明
核心能力给自选股设置成本价，显示现价 vs 成本的盈亏率；填了数量再显示盈亏额
录入方式自选面板行内 hover「成本」按钮 → 弹小窗输入成本价（数量可选）→ 保存
展示位置① 自选面板每行：小字「成本 12.34 · 盈亏 +8.5%」；② 自选悬浮提示：成本价 / 盈亏额 / 盈亏率三行
配色盈亏正红负绿（与现价涨跌一致），未设成本不显示
数据安全双写：localStorage 即时 + 服务端 costs.json（防清浏览器丢失），服务不可达静默降级
数据模型{ "600519": { "cost": 1500.5, "qty": 100, "updated_at": 1786416000 } }qty 可缺省（不填则只显示盈亏率）
✓ 数据源纪律合规：成本价是用户手动录入，不依赖任何外部接口，天然符合「无鉴权公开数据源」约束。

二、方案对比

方案存储优点缺点结论
A · 纯本地仅 localStorage零服务端改动，最快清浏览器数据即丢（用户已踩过自选丢失的坑）不推荐
B · 服务端双写localStorage + costs.json（GET/POST /api/costs）与备注/自选备份同构、防丢、离线降级服务端约 60 行 + 前端约 140 行推荐
C · 并入 watchlist塞进 watchlist.json 条目少一个文件耦合自选结构、与 v57 备份混存、截断逻辑冲突风险不推荐
D · 备注里解析note 文本内嵌「成本:12.34」零新 UI备注是自由文本，解析脆弱、展示不可控不推荐

方案 B 与 v37 备注、v57 自选备份完全同构：前端一个对象 + 保存函数双写 + 加载时服务端优先兜底，风险最低。

三、盈亏计算规则

指标公式说明
盈亏率(现价 − 成本) ÷ 成本 × 100%必显（有成本即显示），红涨绿跌
盈亏额(现价 − 成本) × 数量仅当填了数量才显示，金额千分位格式化
现价来源data.json + 盘中 8 秒轮询自选面板现价已实时，直接复用，无需新增行情请求

五、风险与边界

风险 / 边界处置
现价是快照（收盘后静态）与全站一致，收盘后盈亏冻结在收盘价，属预期行为
成本价录错 / 要改随时可重新编辑；编辑窗提供「清空」删除成本
服务不可达静默降级纯本地（同备注），恢复后下次保存自动回传
除权除息 / 分红摊薄成本不做自动调整（需行情事件源，超范围），用户手动更新成本价即可
持仓汇总面板（总盈亏）v64 不做，可后续 v65 扩展（本功能数据模型已支持）
接入券商真实持仓不做：需登录鉴权接口，违反数据源纪律

六、验收标准

  1. 给自选股设成本价后，自选行出现「成本 + 盈亏%」，颜色正确（盈红亏绿）
  2. 填数量后悬浮提示显示盈亏额，未填数量不显示金额
  3. 清空浏览器数据 + 刷新，成本价从服务端恢复（同自选备份行为）
  4. 成本价支持编辑与清空；非法输入（负数 / 非数字）被服务端清洗拒绝
  5. 期货等非 A 股品种同样可用（code 维度通用）
