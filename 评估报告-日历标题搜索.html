日历标题搜索功能评估与实施计划

a-share-heatmap · 拟版本 v87 · 2026-09-11 · 评估结论：可行且推荐实施，纯前端改造，零服务端/零数据源改动，约 90 行、5 个步骤、半个版本工作量

核心结论

在日历工具栏（cal-bar）加一个标题搜索输入框：输入关键词实时过滤事件列表，匹配日自动展开、命中片段高亮、显示匹配计数；清空即恢复原视图。日历数据全部在前端内存（calendar.json 每次全量下发，当前 211 条 / 13 天），过滤就是一次内存 includes()，零后端改动、零新增数据源。现有过滤管线（星级/类型 pill）已有同构插槽，接入点唯一且清晰。

项说明

交互形态工具栏输入框，输入即过滤（200ms 防抖）；标题命中片段高亮；Esc / × 清空恢复

展开联动搜索激活期间：有命中的日强制展开（无视折叠态），无命中的日隐藏；清空后恢复用户折叠态

二、现状事实（评估依据）

事实数值 / 位置对评估的影响
数据量211 条事件 / 13 个日期 / 14 个国家（calendar.json 实测）内存过滤毫秒级，无需索引、无需防抖以外的性能设计
标题语言构成210 条含中文，86 条含英文字母（CPI、EIA、GDP、FOMC 等缩写）必须大小写不敏感（用户输入 "cpi" 要能命中 "CPI"）；中文直接 includes
标题长度5~34 字符，均值 13.9高亮注入简单，无超长截断问题
数据生命周期前端 calItems 常驻，服务端每 5 分钟刷新落盘，前端 120s 拉取搜索词过滤的是最新数据，30s/120s 重渲染天然继承搜索态
现有过滤管线app.js renderCalendar 内 vis 过滤（calImp + calType 两条件）搜索条件是第三个 &&，接入点唯一
空态处理「当前过滤条件下无事件」已有搜索 0 命中复用，仅换文案
浏览器 Ctrl+F 的缺口折叠日的 body 是 display:none，Ctrl+F 搜不到；13 天中默认仅 8 天展开这是本功能的核心价值：Ctrl+F 无法覆盖折叠内容，且 30s 重渲染会打断查找高亮

三、方案设计

决策点选项结论
匹配范围 A. 仅标题　B. 标题 + 国家名（找「美国」全部事件） A · 仅标题（推荐）功能名即「标题搜索」，语义可预期；B 的一字之差成本极低（一个 ||），但「美国」会命中 60+ 条刷屏，且国家已有类型/星级维度可缩窄，留作 v1.1 开关
搜索期展开策略 A. 命中日强制展开（只读覆盖）　B. 维持用户折叠态　C. 把命中日写入 calExpandedDays A · 强制展开（推荐）B 会让命中日藏在折叠里（功能形同虚设）；C 会污染用户折叠态，与 v87 刚修复的「继承式手动模式」（calExpandedDays 首次点击继承现状）相冲突——清空搜索后用户自己的折叠选择被改写。A 在 calDayHtml 里只读判断 calQuery ? true : 原逻辑，不碰 Set
高亮实现 A. 不高亮　B. 命中片段 <mark> 高亮 B · 高亮（推荐）先 calEsc 转义全文，再按大小写不敏感索引切三段拼 span（~10 行），杜绝 XSS：标题来自华尔街见闻外部源，必须先转义再注入
输入框位置 A. cal-bar 类型 pill 之后　B. 锚点按钮之前 A（推荐）「筛选维度从粗到细」的阅读顺序：锚点 → 星级 → 类型 → 关键词；cal-bar 已 flex-wrap，窄屏自然换行，仅需补 min-width
今日重点（焦点卡） A. 搜索期间隐藏　B. 保持显示 A · 隐藏并复用其标题行（推荐）搜索时用户注意力在结果上，焦点卡反而干扰；标题行正好用来显示「搜索 "xxx" · N 条匹配」

四、与既有机制的交互（关键风险点逐条核对）

  • 30s 倒计时重渲染 / 120s 数据重拉：搜索词是模块级变量（同 calImp），重渲染自动继承；输入框位于 cal-bar（calList 之外），innerHTML 重建不会打断输入焦点——这是把输入框放 cal-bar 而非列表区的原因。
  • 折叠状态（v87 刚修复的继承逻辑）：搜索期展开是 calDayHtml 的只读覆盖，不写 calExpandedDays；清空搜索后按原逻辑（null=默认规则 / Set=手动模式）恢复，互不污染。用户在搜索期间点击天头部仍正常写 Set，与强制展开叠加无害（清空后以 Set 为准）。
  • IME 中文输入法：必须处理。拼音组词过程会连续触发 input 事件（输入 "feinong" 中途每个字母都过滤一次），需 compositionstart/end 标志位跳过组词期、compositionend 时再过滤；否则界面闪烁且中途态无意义。这是中文应用搜索框的标配处理。
  • 锚点按钮（今日/本周/下周）：搜索把目标日滤掉时 scrollIntoView 落空，现有 else 分支已弹「该日期范围暂无事件」toast，无需改动。
  • 「新/升」标记与匹配叠加：is_new/upgraded 徽标在行内渲染，与标题过滤正交，天然共存。
  • 移动端：cal-bar 无专属媒体查询规则，靠 flex-wrap；输入框补 flex:1 1 140px; min-width:120px 即可在窄屏占满一行，与页首股票搜索框（#search）的响应式处理同构。
  • XSS：标题为外部抓取内容，高亮路径必须「先转义、后注入」；非高亮路径沿用现有 calEsc 不变。

五、实施步骤（拟 v87a~v87e）

1
v87a · 工具栏与状态（index.html + app.js ~20 行）
cal-bar 类型组后加输入框（placeholder「搜索事件标题」+ × 清空按钮），CSS 补宽度规则；app.js 加 calQuery 状态与 200ms 防抖 input 监听（含 IME composition 守卫、Esc 清空）。
2
v87b · 过滤接入（app.js ~15 行）
renderCalendar 的 vis 过滤加第三条件：!calQuery || it.title.toLowerCase().includes(calQuery)；0 命中空态文案区分「无匹配 "xxx"」。
3
v87c · 搜索期展开（app.js ~10 行）
calDayHtml 展开判断改为：calQuery 非空时恒 true（只读覆盖，不写 calExpandedDays）；今日重点区隐藏，标题行改显匹配计数。
4
v87d · 标题高亮（app.js ~15 行）
calRow 的 ttlt 渲染改为：calEsc 后按不敏感索引切三段，中段包金色 mark 样式（复用 --gold，与 ntag 视觉一致）。
5
v87e · 验证（浏览器实测）
① "cpi" 大小写命中；② 中文词 + IME 组词不闪烁；③ 命中日自动展开、清空后折叠态复原（含手动模式用户）；④ 与三星 pill 叠加；⑤ 0 命中空态；⑥ 30s 重渲染不断焦点、搜索态保持；⑦ 移动端 375px 宽度换行正常。

六、风险与非目标

项等级说明与对策
IME 组词期误过滤中composition 守卫为必做项（步骤 1 内置），漏做会在中文输入时明显闪烁
高亮注入 XSS中先转义后注入，步骤 4 严格约束；非搜索路径零改动
折叠态污染低只读覆盖设计已规避；步骤 3 明确不写 calExpandedDays
拼音 / 繁简匹配非目标需引入字典或数据预标注，收益不成比例；事件标题以官方缩写为主（CPI/EIA），精确子串已覆盖主场景
搜索历史持久化非目标v1 不做；如需可后续 localStorage 存最近 5 词
✓ 总体结论：纯前端、接入点唯一、与刚修复的折叠状态机制正交可控，推荐按 v87a~v87e 实施。
