1. 为什么考虑 pytdx

pytdx 是通达信行情协议的 Python 实现，直连券商/行情服务器，理论上有三个优势：

  • 更实时：协议级行情，比东财网页接口的延迟行情更接近 Level-1 实时
  • 无网页风控：不依赖 HTTP 网页接口，绕开反爬断连问题
  • 免费无 token：无需任何 API Key

本机实测（扫描 pytdx 内置 104 台服务器 + 真实行情压测），逐一验证上述假设。

2. 实测结果：字段覆盖

热力图所需字段pytdx 可得性获取方式与代价
股票代码 / 名称部分列表接口 get_security_list 在 104 台服务器中 0 台可用；需从其他源（东财）导入代码表
现价 / 涨跌幅 / 成交额可得get_security_quotes 批量行情，上限 80 只/次，涨跌幅需用 (现价-昨收)/昨收 自算
总市值（方块权重）间接无直接字段；get_finance_info 返回总股本，×现价可得，但需逐股请求（实测 20 只 0.95s，全市场 5400 只约 255s）
行业分类间接无行业板块文件（仅概念/风格/指数板块）；get_finance_info 有 industry 字段但同样逐股获取，且为通达信粗分类（约 60+ 类）

5. 建议

  • 维持东财数据源：本次实测 5545 只全量抓取成功（约 7 分钟，含大量重试），增量刷新会快得多；把刷新频率设为 3-5 分钟一次即可稳定运行。
  • pytdx 定位为可选增强层：若将来确实需要"接近实时的价格跳动"，可做混合方案——东财每 5 分钟更新代码表/市值/行业，pytdx 用 3-5 台服务器并行、每台 25 次请求分摊 70 次总量，实现 20-30s 一轮价格刷新。需要的话我可以实现。
  • 不做的原因：热力图的核心价值是"全市场结构一眼看"，8 秒延迟行情已足够；为省 5 秒延迟引入服务器池运维（健康检查、冷却、故障转移），投入产出比低。
