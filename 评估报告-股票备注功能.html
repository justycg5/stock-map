结论：可行，推荐实施。 现有悬浮窗（tooltip）结构与交互机制天然支持备注展示与内嵌编辑，预估改动 JS ~70 行 + CSS ~25 行，无数据源依赖、无网络请求，风险低。唯一需要专门处理的点是「编辑态防重渲染」——已确认现有 tooltip 锁定机制可复用，方案明确。

一、现状盘点（已核实代码）

悬浮窗 updateTooltip(node, mx, my)

鼠标悬停个股时展示：名称+代码 / 现价 / 区间涨跌幅 / 当日涨跌幅 / 涨跌额 / 成交额 / 总市值 / 行业 / 「☆ 加自选」按钮。数据全部来自内存中的 node（由 data.json 快照构建），无额外请求。

三个可复用的既有机制
  • tooltip 锁定（tooltipLocked）：鼠标移入浮层后 mousemove 直接 return，浮层内容不再被重建——内嵌输入框天然不会被打断。
  • 事件委托：tooltip 已有 click 委托处理「加自选」按钮，备注按钮/保存可挂同一委托。
  • localStorage 自选存储：备注可照搬同一套读写模式（key + JSON + 异常兜底）。

二、推荐方案

数据模型：独立于自选的备注表
项设计
存储localStorage key wl_notes_v1，值为 {"600519": "白酒龙头，关注批价", ...}（code → 备注文本）
与自选关系完全独立——非自选股也可加备注、查看备注；删除自选不影响备注
覆盖范围任意个股（叶子节点）；行业节点（非叶子）不支持备注（无明确语义）
长度上限200 字，超出截断提示
安全渲染前 HTML 转义（复用 esc），防注入
UI：悬浮窗内嵌备注区（三级状态）
1无备注：显示「＋ 备注」小按钮
2有备注：显示备注文本（保留换行）+ 「编辑 / 删除」
3编辑态：textarea + 保存/取消（不打断输入）

备注区位置：行业行之后、「加自选」按钮之前。长文本 max-width + max-height + 滚动，不撑爆悬浮窗。

三、交互流程

1悬停个股 → 悬浮窗出现，读取备注并渲染对应状态
2点击「＋ 备注 / 编辑」→ 进入编辑态（noteEditingCode 置位）
3textarea 输入 → 期间 updateTooltip 被编辑态标志拦截，浮层冻结不重建
4点「保存」→ 写入 localStorage + 更新展示态；「取消/删除」→ 还原或清除
✓ 输入不打断：编辑态标志 + 既有 tooltipLocked 双保险，鼠标在浮层内移动/输入不受任何重渲染干扰。

五、边界与风险

  • 换浏览器 / 清站点数据 → 备注丢失：与自选股同性质（localStorage 存储）。如在意，后续可加「导出/导入 JSON」一并覆盖自选 + 备注。
  • 编辑中浮层被其他事件隐藏（如点 canvas 空白）：textarea 未保存内容丢失。风险低（编辑中鼠标在浮层内），首版接受；如需更稳可加「未保存离开提示」。
  • 备注长文本：限定 max-height + 滚动 + 200 字上限，悬浮窗宽度受控。
  • 股票改名/退市：备注以 code 为键，名称变化不影响；退市股备注成孤儿数据（无害，可忽略或清理）。
  • 二级页（个股网格详情浮层）：首期不做，仅主画布悬浮窗；如需扩展，二级页浮层是独立渲染函数，可复用存储层。

七、待你拍板的三个选项
