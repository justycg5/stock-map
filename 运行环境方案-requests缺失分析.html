二、四种方案对比

方案成本抗 AutoClaw 更新未来扩展（pytdx 等第三方库）评价
A. urllib 兼容层（已实施）已完成，零成本完全免疫——纯标准库，任何 python 都能跑不支持，需另想办法当前最优，根治
B. pip 装 requests 进内置环境一条命令脆弱——更新即被重置（本次事故就是这么来的）每次更新后需重装治标不治本，不推荐
C. 独立官方 Python（用户提议）下载安装 + 改启动脚本完全隔离，更新不影响有 pip，可任意装包当前用不上，为将来留门
D. 独立 Python + venv同 C + 建 venv同 C最佳实践，依赖隔离项目当前零依赖，venv 闲置

三、最优方案判定

结论：现在不需要安装独立 Python 环境

  • 兼容层方案 A 已让项目零第三方依赖（server.py / fetch_data.py / fetch_spot.py 全部标准库），AutoClaw 更新、换 python、换机器都不影响——这是对"更新会重置环境"这类问题最彻底的解法。
  • 安装独立 Python（方案 C/D）解决的是「未来要用第三方库」的问题，而不是当前问题。当前没有第三方库需求，装了也闲置。
  • 唯一明确的未来候选：pytdx（通达信行情，之前可行性分析过，若接入需第三方包）。届时再装官方 Python 也不迟，一条安装命令 + 改 start.bat 指定解释器路径即可，迁移成本很低。

四、如果将来要装独立 Python（备用方案）

安装与接入步骤（到时再执行）

  • 从 python.org 安装官方 Python（勾选 Add to PATH）；本机目前无 py launcher，装官方版可顺带获得
  • 项目建 venv：python -m venv D:\autoagent_file\a-share-heatmap\.venv
  • start.bat 改为显式调用 .venv\Scripts\pythonw.exe server.py 8080（不再依赖 PATH 解析）
  • server.py 子进程调用保持 sys.executable——venv 启动后自动使用 venv 内 python，无需改代码
  • 需要第三方包时 .venv\Scripts\pip install 包名，与 AutoClaw 环境完全隔离
